# Proposal

## Why

Для будущих проверок занятия нужны данные, которыми владеет `people-stub`: профиль преподавателя, его недельная доступность и вместимость аудитории. WP-02 готовит получение этих данных для сценариев следующих пакетов (FR-12).

## What Changes

- Добавить типизированный асинхронный клиент трёх предметных эндпоинтов. Адрес берётся из `STUB_BASE_URL`, каждый вызов ограничен `STUB_TIMEOUT_MS`. HTTP-клиент закрывается при остановке приложения.
- Собирать профиль и доступность одновременно. Для `IN_PERSON` одновременно запрашивать и аудиторию. Независимость запросов позволяет сократить общее ожидание по сравнению с последовательными вызовами.
- Обрабатывать `404` заглушки как отсутствие преподавателя или аудитории. Преобразовывать `5xx` и таймаут в контрактные ошибки `502 UPSTREAM_UNAVAILABLE` и `504 UPSTREAM_TIMEOUT`.
- Подтвердить перекрытие вызовов и выигрыш по времени тестом с фейковым клиентом без сети. Записать в README команду и полученные результаты (NFR-07).

## Capabilities

### New Capabilities

- `people-client` — получение данных преподавателя и аудитории для проверки занятия с обработкой отказов внешнего сервиса.

### Modified Capabilities

Нет.

## Impact

Изменения затронут клиент внешнего сервиса, сборку данных для проверки занятия, жизненный цикл приложения, обработку ошибок, тесты и README. Подключение к созданию и валидации занятий относится к WP-03. Чтение групп и занятий, seed и reset сохраняют независимость от `people-stub`.
